## 1. What changed this session, file by file

### `linux-plus-quest/index.html` (the whole app: CSS, HTML, question bank, engine)

Bug fixes:
- **Exam timeout bug.** After an exam ran out of time, the next normal game was
  scored as a failed exam. Added one function, `resetMode()`, which clears every
  mode flag, the question timer and the exam clock. Every screen and mode entry
  point calls it first.
- **Storage crashes.** Added a `store` object (`get`, `set`, `del`, `obj`) that
  wraps `localStorage` and never throws. All saving and loading goes through it.
- **Scoring.** The grading code existed three times (`pick`, `pickMulti`,
  `pickFill`). It is now one function, `grade()`. Rank is based on the fraction
  answered correctly (`S.correct / total`), not on points. A tied high score no
  longer says "New high score!". An empty fill-in answer is ignored instead of
  costing a life.
- **Keyboard.** Enter on a focused button no longer also triggers NEXT/RETRY.
  Flashcards: arrow keys move, Space flips. Multi-select: E/F and 5/6 keys work.
- **Accessibility.** Subject cards, difficulty cards and the flashcard are now
  `role="button"` with `tabindex="0"`. Feedback is announced to screen readers
  (`aria-live`). Star and multi-select buttons report pressed state. Added a
  focus ring, reduced-motion support, and raised the dim text colour (`--dim`)
  from about 4:1 to about 8:1 contrast.
- **Content.** Corrected five Linux+ explanations (static route persistence,
  `chgrp`, `chattr +i`, `grep -c`, `journalctl`). Only the `e` (explanation)
  text changed.
- **Exam sim wording.** The badge shows the real question count, and a pass no
  longer claims "you'd pass the real exam".
- **Housekeeping.** Stale title and subtitle text updated. Removed the
  `frame-ancestors` rule from the security header, because browsers ignore it
  there and it only produced a console error.

New features:
- **Daily Review (spaced repetition).** `getDueQuestions()`, `startDue()`, and
  two new fields (`box`, `due`) written by `recordStat()`.
- **Progress dashboard.** `showDashboard()`, `subjectReport()`, opened from a
  new PROGRESS button on the home screen.
- **XP and day streak.** `loadMeta()`, `bumpMeta()`, `currentStreak()`, saved
  under a new storage key `tq_meta`.
- **Export / Import.** `exportProgress()`, `importProgress()`, `allKeys()`.

### `linux-plus-quest/sw.js` (offline support)
Rewritten. It was "cache first" (serve the saved copy forever). It is now
"network first" (newest version when online, saved copy when offline). Fully
commented.

### `linux-plus-quest/manifest.json` (install settings)
Name changed to TechQuest. Icon entries fixed.

### `linux-plus-quest/icon-192.png`, `icon-512.png` (new)
The manifest pointed at these but they never existed, which blocked "Install".
They are a simple green `>_` on a dark background, generated by a script.

### `linux-plus-quest/PROJECT_NOTES.md`
Removed the owner's personal email address (the repo is public).

### `linux-plus-quest.html` (deleted)
The original prototype. Nothing linked to it.

### `.gitignore` (new)
Ignores `null`, `.claude/`, `New folder*/`, `*.log`.

## 3. Known bugs and things I was not sure about

- **The Linux+ content targets a retired exam.** The app says XK0-005, which
  retired on 2026-01-13. The current exam is XK0-006. There are only 59 Linux
  questions and none cover containers, Git, Ansible, Python, LVM, GRUB,
  AppArmor, PAM or nmcli.
- **Only the 59 Linux questions were fact-checked.** The other 485 passed
  structural checks (valid answer indexes, no duplicates, no blank options) but
  their facts were not reviewed.
- **Correct answers are often the longest option** (27 of 55 Linux multiple
  choice questions). A test-wise student can guess them. Not fixed.
- **Editing a question's text resets its history.** A question's ID is a hash of
  its text, subject and level (`qid()`). Changing `q.q`, `sub` or `lvl` makes a
  new ID. Changing the explanation or the answers does not.
- **Exam sim for Linux always uses the same 59 questions**, because the pool is
  smaller than the 60 it wants.
- **The hint is free when your score is 0** (the cost cannot go below zero).
- **The HARD timer drifts** if the browser tab is in the background.
- **Day streak near a clock change.** "Yesterday" is worked out as "now minus 24
  hours", which can be wrong for an hour around a daylight-saving change.
- **Readiness is a rough estimate**, calculated as accuracy × coverage. It is
  not calibrated against real exam results.
- **Service worker is network-first for every file.** On a very slow connection
  the app waits for the network before falling back to the saved copy.
- **The repo's git history still contains the email address** that was removed
  from `PROJECT_NOTES.md`. Removing it fully would need a history rewrite.
- **Local junk not deleted:** the file `null` and two empty `New folder`
  directories are still on disk. They are ignored by git, not removed.

## 5. How to run and test from scratch

You need Git and Python (any 3.x). Node is only needed for scripts.

```bash
git clone https://github.com/JDJ760/LINUX-PLUS-QUEST.git
```

```bash
cd LINUX-PLUS-QUEST
```

```bash
git checkout fixes-and-upgrades
```

```bash
python -m http.server 8765 --directory linux-plus-quest
```

Then open `http://localhost:8765` in a browser.

Use a local server, not a double-click on the file. Opened as `file://`, the
service worker and install features do not run.

Manual test checklist:
1. Home screen: press Tab. A cyan ring should move across the subject cards.
   Press Enter on one.
2. Play a BEGINNER round. Get a few wrong on purpose. Check the rank at the end
   matches your percentage.
3. Go back to the subject. A DAILY REVIEW card should appear with the questions
   you missed.
4. Home → PROGRESS. Check streak, XP, the subject table and weakest topics.
5. Click EXPORT. A `techquest-progress-YYYY-MM-DD.json` file should download.
6. Click IMPORT and choose that file. Progress should be unchanged.
7. Start an EXAM SIMULATION, quit, then play a normal round. The result screen
   must say SESSION COMPLETE, not anything about an exam.
8. Browser dev tools (F12) → Console tab. There should be no red errors.
9. Dev tools → Application tab → Service Workers → tick "Offline", reload. The
   app should still load.

To see saved data: dev tools → Application → Local Storage. All keys start with
`tq_`: `tq_stats` (per-question history), `tq_starred` (bookmarks), `tq_meta`
(XP and streak), and `tq_<subject>_<level>` (high scores).

## 6. Decisions and why (please do not undo these by accident)

- **No frameworks, no dependencies, no build step.** The owner maintains this
  alone and is learning the code. Everything is plain HTML, CSS and JavaScript
  in one file.
- **All storage goes through `store`, never `localStorage` directly.** A direct
  call can throw and crash the app when storage is blocked or full.
- **Every mode entry point calls `resetMode()` first.** Clearing flags by hand
  in each start function is exactly what caused the exam timeout bug. If you add
  a new mode or a new flag, add the flag to `resetMode()`.
- **Grading happens only in `grade()`.** Do not put scoring back into
  `pick`, `pickMulti` or `pickFill`.
- **Rank uses correct answers, not points.** Points include streak bonuses,
  which made 80% look like 95%.
- **Question text is data, never HTML.** Every question field goes through
  `esc()` before it is put on the page. This prevents text like `<iostream>`
  from vanishing and prevents script injection. Keep doing this for any new
  field.
- **Imported files are untrusted.** `importProgress()` only accepts `tq_` keys
  with the expected shape. Do not loosen this.
- **Service worker is network-first.** The old cache-first version meant users
  never got updates unless a version string was hand-edited. The trade-off is a
  slower start on a bad connection, which was judged acceptable.
- **Cards are `div role="button"`, not `<button>`.** This was the smallest
  change that made them keyboard-usable without restructuring the card HTML. A
  key handler forwards Enter and Space to a click. Converting them to real
  buttons later is fine.
- **Spaced repetition uses simple Leitner boxes** (gaps of 0, 1, 3, 7, 14, 30
  days), not the more complex SM-2 algorithm from `ROADMAP.md`. It is about ten
  lines and easy to explain. Old saved data without a `due` field is handled.
- **The dashboard stores nothing.** It is recalculated from `tq_stats` each time
  it opens, so it cannot drift out of sync. Only XP and streak are saved.
- **Question IDs were left as text hashes.** Switching to fixed IDs would be
  more robust but would orphan everyone's existing history, so it was deferred.
- **The Linux+ retarget was deferred by the owner**, not forgotten.
- **Work is on a branch and unpushed** because pushing `main` updates the live
  site immediately.
